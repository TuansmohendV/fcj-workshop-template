### Week 2 Objectives:

- **Research and learn about the AWS services used in the practical project:**
    - **Amazon VPC (Virtual Private Cloud):** Create a distinct virtual network environment to deploy AWS resources.
    - **Amazon EC2 (Elastic Compute Cloud):** Provide virtual servers to run the FCJ Management application.
    - **Amazon RDS (Relational Database Service):** A managed relational database service to store application data.
    - **Amazon EC2 Auto Scaling:** Automatically adjust the number of EC2 instances based on actual demand.
    - **Elastic Load Balancing (ELB):** Distribute incoming traffic across multiple EC2 instances.
    - **Amazon CloudWatch:** Monitor AWS resources and applications, collect, and track metrics.
    - **AWS Systems Manager:** Manage configuration and automate tasks on EC2 instances.

### Weekly Tasks:

- Study official documentation (AWS Documentation) regarding core infrastructure services: VPC, EC2, and RDS.
- Read and understand the operational mechanisms of Elastic Load Balancing and Auto Scaling to prepare for future system performance optimization.
- Learn the theoretical concepts of remote resource monitoring and management via CloudWatch and Systems Manager.

### Week 2 Outcomes:

- **Completed theoretical research on AWS network infrastructure and core servers:**
    - Mastered the concepts of **Amazon VPC**, understanding Public/Private Subnet division and the traffic routing roles of Internet Gateways and NAT Gateways.
    - Gained a clear understanding of the provisioning and management mechanisms of **Amazon EC2** virtual servers, preparing for the actual application deployment steps.
    - Acquired knowledge of the **Amazon RDS** managed database model and secure data storage options.

- **Approached theoretical concepts of system scalability and monitoring:**
    - Understood the collaborative principles between **ELB** and **EC2 Auto Scaling** in automating load balancing and ensuring High Availability for the system.
    - Grasped the theory behind using **Amazon CloudWatch** to track resource metrics and how **AWS Systems Manager** supports centralized configuration management.
