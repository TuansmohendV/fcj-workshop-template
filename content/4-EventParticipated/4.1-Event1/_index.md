# "Mini meetup" Event Summary 

### Overview of the Attended Event

On May 30, 2026, I had the opportunity to attend the Mini meetup program as an audience member and an observing learner. This program was organized to foster boldness in thinking and doing, the courage to present personal viewpoints, and the willingness to debate on chosen topics, aiming to understand one another better and grow together with Amazon Web Services (AWS).

### General Information:

**Time:** 09:00, May 30, 2026

**Location:** 26th Floor, Bitexco Financial Tower, 02 Hai Trieu Street, Saigon, Ho Chi Minh City

**Activity Name:** Mini meetup

**Format:** Sharing personal viewpoints and debating

**Role:** Participant

**Main Content:** Topics self-selected by the speakers, sharing knowledge learned and personal achievements during their internship.

### Open-Source Tool: Floci (Open-Source Floci)

Floci is an open-source AWS Local Emulator that is completely free, carrying the tagline "Light, fluffy, and always free".

Practical Learning Roadmap: The speaker shared a very clear 3-phase roadmap for cloud beginners:

Phase 1 (Phase 1 - Mind & Architecture): Developing architectural thinking through the interactive platform AWS Cloud Quest.

Phase 2 (Phase 2 - Code & Fast Testing): Writing source code and conducting fast, safe testing by utilizing Open-Source Floci directly on the local machine without worrying about incurring costs.

Phase 3 (Phase 3 - Real Deployment & Production): Deploying the actual system onto the Real AWS environment.

**Lessons Learned:** Learning about Floci opens up a new mindset for me in optimizing the software testing process, allowing fast experimentation with Cloud features without financial pressure on a real AWS account.

### Hackathon Project: AI Voice Verification System - SynthHunter
Current AI technology can forge voices to bypass traditional security layers, posing major risks regarding fraud and legal compliance.

Applied Solution: The team presented the SynthHunter solution – an intelligent audio classification system designed to determine whether speech recordings are spoken by humans (HUMAN), generated by artificial intelligence (AI GENERATED), or require further review (NEEDS REVIEW).

Core Architecture: The system operates based on a Three-Pillar Detection Engine:

Speech Dynamics: Utilizing the XLS-R model.

Encoder Behavior: Utilizing the Whisper solution.

Temporal Rhythm: Analyzing the rhythm and pauses in speech (Pause Analysis).

**Lessons Learned:** This topic helped me see the high practicality of AI-powered security solutions, while also deepening my understanding of how to combine advanced audio analysis models to resolve a pressing cybersecurity vulnerability today.

### Infrastructure Migration Plan for the "Tu vi Dai Viet" Project

This is a real-world destiny decoding and self-understanding application that already has live products (Website, Facebook, Instagram) and is planning to optimize its system through Cloud Migration.

Comparison of Infrastructure Structure (Current Stack vs AWS infra migration):

Current Infrastructure: The system utilizes a traditional model with the Backend/Frontend running on a virtual private server VPS (Nginx + PM2), storing data using MySQL, calling OpenAI's API (GPT-4.5) to process intelligent logic, and using Redis as a cache database.

Target Infrastructure for AWS Migration: The project aims for a more sustainable architecture by migrating the Backend/Frontend to run on Amazon ECS and Amplify Hosting, while shifting the database to Amazon RDS. Specifically, the AI processing part will be replaced by Amazon Bedrock to optimize LLM integration, combined with Amazon ElastiCache to accelerate data retrieval speed and CloudWatch/Lambda to operate background jobs.

**Lessons Learned:** This is an incredibly valuable real-world case study for me. It helps me clearly understand the thought process of an engineer when converting a system from a traditional server to an AWS environment to achieve high availability, security, and long-term scalability.

### Discussion Atmosphere and Debating Activities

Alongside the rich professional content, the highlight that made the Mini meetup appealing was the open interaction space and the direct debating activities after each presentation:

The Spirit of Daring to Think, Daring to Speak: The intern speakers demonstrated a highly confident spirit when presenting their personal viewpoints. Civilized and Multi-dimensional Debate: Interrogative questions from the audience and the advisory board helped deepen the technical expertise of the topics. This debating process not only helped presenters identify areas that need optimization in their architecture but also trained observing participants like me in analytical thinking, viewing a technical problem from multiple perspectives.

### Personal Takeaways and Future Orientations
After the conclusion of the Mini meetup, I accumulated valuable lessons for my own development journey:

Regarding Soft Skills: True to the original purpose of the event, I realized the importance of daring to defend personal viewpoints and communication skills. A technology engineer not only needs to be good at technical expertise but also must know how to express and present their solutions coherently and convincingly to the listeners.

Application Orientation: This knowledge regarding network design models, database connectivity, and cloud infrastructure migration will be studied further by me to apply to upcoming projects, major assignments, and technology capstones at university.
